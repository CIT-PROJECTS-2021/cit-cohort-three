# Object-Oriented Programming (OOP)

OOP models real‑world things as objects with data (attributes) and behavior
(methods).

<Callout type="info">
Objects group **data** and **behavior** together, which keeps code organized.
</Callout>

## Core Ideas
- **Class**: blueprint for objects
- **Object**: instance of a class
- **Encapsulation**: keep data and behavior together
- **Inheritance**: reuse behavior from a base class
- **Polymorphism**: same interface, different implementations
- **Abstraction**: hide complex details behind a simple interface

## Quick Example
```python
class Dog:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return f"{self.name} says woof"

pet = Dog("Rex")
print(pet.speak())
```

**Class vs object**
- A class is the blueprint.
- An object is the actual thing built from the blueprint.

## OOP in Practice
Use classes when you want to:
- Group data and behavior together.
- Reuse logic via inheritance.
- Model real-world entities (User, Order, Product).

## Common Mistakes
- Forgetting `self` in methods.
- Putting unrelated responsibilities in one class.
- Overusing inheritance where composition would be simpler.
