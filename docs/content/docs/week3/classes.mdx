A class is a blueprint for creating objects with attributes and methods.

<Callout type="info">
Use classes when you want to model a real‑world thing with data and behavior.
</Callout>

## Example
```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def greet(self):
        print(f"Hi, I'm {self.name}")

person = Person("Ada", 28)
person.greet()
```

**Expected output**
```
Hi, I'm Ada
```

## Key Ideas
- `__init__` initializes a new object.
- `self` refers to the current instance.

## Additional Example: Student
```python
class Student:
    def __init__(self, name, student_id):
        self.name = name
        self.student_id = student_id

    def info(self):
        return f"{self.name} ({self.student_id})"

student = Student("Lara", "ST-102")
print(student.info())
```

**Expected output**
```
Lara (ST-102)
```

## Rules

1. **Define with `class Name:` and an indented body.**
2. **`__init__` runs on instantiation and must return `None`.** Returning anything else raises `TypeError`.
3. **Instance attributes are created by assigning to `self.something`**, normally inside `__init__`.
4. **`self` is a convention, not a keyword** — but always use it; it must be the first parameter of every instance method.
5. **Access instance state through `self` inside methods.** A bare `name` refers to a local variable, not `self.name`.
6. **Reading an attribute that was never assigned raises `AttributeError`.**
7. **Mutable class attributes are shared across all instances.** Put per-instance state in `__init__`.
8. **`__str__` controls what `print(obj)` shows** and must return a string.

## Common Mistakes
- Forgetting `self` in method definitions.
- Setting attributes outside `__init__` without a reason.
- Using classes when a simple dictionary would do.
