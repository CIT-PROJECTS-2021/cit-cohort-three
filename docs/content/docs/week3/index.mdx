A variable holds one value. Real programs hold many, and the shape you store them
in decides how easy the rest of your code is to write.

This week covers the five types you'll reach for constantly, and the question
that picks between them: does order matter, can it change, and do you look things
up by position or by name?

<Callout title="Before you start">
You need [Week 2](/docs/week2), especially
[for Loops](/docs/week2/for-loops) and
[Membership operators](/docs/week2/operators-membership). Every collection here
is something you will loop over.
</Callout>

## What you'll learn

- Slice, format, and search text with string methods
- Choose between a list, tuple, set, and dictionary for a given job
- Iterate over each one, including key/value pairs
- Nest collections to model data with more than one dimension

## Choosing one

| You need | Use |
| --- | --- |
| An ordered list you'll add to and change | [List](/docs/week3/lists) |
| An ordered group that must not change | [Tuple](/docs/week3/tuples) |
| Uniqueness, or a fast "is this in here?" | [Set](/docs/week3/sets) |
| Lookup by name rather than position | [Dictionary](/docs/week3/dictionaries) |
