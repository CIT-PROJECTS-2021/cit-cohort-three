Both composition and inheritance help you reuse code, but they solve different
problems.

## Inheritance (is‑a)
Use inheritance when one class **is a** specialized version of another.

```python
class Vehicle:
    def move(self):
        return "Moving"

class Car(Vehicle):
    pass
```

## Composition (has‑a)
Use composition when one class **has a** dependency or component.

```python
class Engine:
    def start(self):
        return "Engine started"

class Car:
    def __init__(self):
        self.engine = Engine()

    def drive(self):
        return self.engine.start()
```

## Quick Comparison
- **Inheritance** shares behavior through a parent class.
- **Composition** builds behavior using smaller parts.

## Rules

1. **Inheritance expresses "is-a"; composition expresses "has-a".** Choose by which sentence is true.
2. **A subclass must be usable anywhere its parent is.** If it has to break or ignore inherited behaviour, it shouldn't inherit.
3. **Prefer composition by default.** Reach for inheritance only when the is-a relationship is genuine.
4. **Keep inheritance shallow.** More than two or three levels becomes hard to follow and change.
5. **Never inherit purely to reuse code.** That's what composition and plain functions are for.
6. **Composed objects are ordinary attributes** — set them in `__init__` and delegate to them in methods.

## Common Mistakes
- Deep inheritance trees that are hard to change.
- Using inheritance for code reuse when composition is clearer.
