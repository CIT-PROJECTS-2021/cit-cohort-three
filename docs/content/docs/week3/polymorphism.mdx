Polymorphism lets different classes provide the same interface.

## Example
```python
class Bird:
    def make_sound(self):
        print("Chirp")

class Dog:
    def make_sound(self):
        print("Woof")

def animal_sound(animal):
    animal.make_sound()

animal_sound(Bird())
animal_sound(Dog())
```

**Expected output**
```
Chirp
Woof
```

## Use Cases
- Payment processors with the same `pay()` method
- Drawing shapes with a shared `draw()` method

## Rules

1. **Polymorphism needs a shared method name**, not a shared base class. Python uses duck typing.
2. **Classes sharing an interface must accept compatible arguments** and return compatible results.
3. **Calling a method the object doesn't have raises `AttributeError`** — that's the failure mode of duck typing.
4. **Overriding requires the exact same method name**, spelling and case included.
5. **Prefer a shared method over `isinstance` checks.** A chain of type tests is polymorphism written by hand.
6. **Python has no method overloading by signature.** A second `def` of the same name replaces the first; use default or `*args` parameters instead.

## Common Mistakes
- Relying on type checks instead of shared interfaces
- Mixing unrelated behaviors under one method name
