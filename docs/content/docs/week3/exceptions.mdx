Exceptions are runtime errors that stop normal program flow. You can handle
them with `try` and `except`.

<Callout type="info">
Don’t catch exceptions unless you can recover or show a helpful message.
</Callout>

## Basic Example
```python
try:
    value = int("abc")
except ValueError:
    print("Not a number")
```

**Catching specific exceptions**
```python
try:
    result = 10 / 0
except ZeroDivisionError:
    print("Cannot divide by zero")
```

## Why Exceptions Matter
Exceptions let you handle errors without crashing the whole program. Good
handling gives users clear feedback and keeps your program stable.

## Multiple Exceptions
```python
try:
    result = 10 / 0
except (ZeroDivisionError, TypeError):
    print("Bad operation")
```

## `else` and `finally`
```python
try:
    num = int("5")
except ValueError:
    print("Invalid")
else:
    print("Valid")
finally:
    print("Always runs")
```

## Raising Exceptions
```python
def positive_only(n: int) -> int:
    if n <= 0:
        raise ValueError("n must be positive")
    return n
```

## Practical Pattern: Input Validation
```python
def read_age():
    while True:
        raw = input("Age: ")
        try:
            age = int(raw)
            if age < 0:
                raise ValueError("Age cannot be negative")
            return age
        except ValueError as e:
            print("Invalid input:", e)
```

## Common Exception Types
- `ValueError`: invalid value (e.g., `int("abc")`)
- `TypeError`: wrong type (e.g., `"3" + 1`)
- `KeyError`: missing dictionary key
- `IndexError`: list index out of range
- `FileNotFoundError`: file doesn’t exist

## Using `try/except` in File Handling
```python
try:
    with open("missing.txt", "r", encoding="utf-8") as f:
        print(f.read())
except FileNotFoundError:
    print("File not found")
```

## Custom Exceptions
You can define your own exception classes to make errors more meaningful.

```python
class InvalidAgeError(Exception):
    pass

def set_age(age):
    if age < 0:
        raise InvalidAgeError("Age cannot be negative")
```

## Logging Errors
Use the `logging` module to record errors instead of only printing them.

```python
import logging

logging.basicConfig(level=logging.INFO)

try:
    value = int("oops")
except ValueError:
    logging.exception("Failed to parse integer")
```

## Rules

1. **`try` must be followed by at least one `except`, or by `finally`.**
2. **Order `except` blocks from most specific to most general.** Only the first match runs, so a broad one first hides the rest.
3. **Never write a bare `except:`.** It catches `KeyboardInterrupt` and `SystemExit` too. Use `except Exception:` at minimum.
4. **`else` runs only when no exception was raised; `finally` runs either way** — including when the `try` block returns.
5. **Custom exceptions must inherit from `Exception`** (directly or indirectly).
6. **`raise` with no argument is only valid inside an `except` block**, where it re-raises the current exception.
7. **Catch only what you can actually handle.** Swallowing an exception and continuing with bad data is worse than crashing.
8. **`except ValueError as e:` binds the exception to `e`**, which is deleted when the block ends.

## Common Mistakes
- Catching all exceptions with `except:` and hiding real errors.
- Printing errors but continuing with invalid data.
- Forgetting to handle `KeyError` or `ValueError` in user input.
