We’ll build a tiny library system with `Book`, `Member`, and `Library` classes.
This shows how objects work together in a realistic way.

## 1) Define `Book`
```python
class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author
        self.is_borrowed = False

    def borrow(self):
        if self.is_borrowed:
            return False
        self.is_borrowed = True
        return True

    def return_book(self):
        self.is_borrowed = False
```

## 2) Define `Member`
```python
class Member:
    def __init__(self, name):
        self.name = name
        self.books = []

    def borrow_book(self, book):
        if book.borrow():
            self.books.append(book)
            return True
        return False

    def return_book(self, book):
        if book in self.books:
            book.return_book()
            self.books.remove(book)
            return True
        return False
```

## 3) Define `Library`
```python
class Library:
    def __init__(self):
        self.catalog = []

    def add_book(self, book):
        self.catalog.append(book)

    def list_available(self):
        return [b.title for b in self.catalog if not b.is_borrowed]
```

## 4) Try It
```python
library = Library()
book = Book("Clean Code", "Robert C. Martin")
member = Member("Ada")

library.add_book(book)
print(library.list_available())

member.borrow_book(book)
print(library.list_available())

member.return_book(book)
print(library.list_available())
```

**Expected output**
```
['Clean Code']
[]
['Clean Code']
```

## Rules

1. **Give each class one responsibility.** `Book` describes a book; `Library` manages the collection.
2. **Initialise every attribute in `__init__`**, so an object is never half-built.
3. **Methods change state through `self`** and return values rather than printing, so they can be tested and reused.
4. **Validate in the method that owns the data**, and raise rather than print on invalid input.
5. **Keep display logic out of the model classes.** Build the string in `__str__`; decide when to print it outside.
6. **Give one class ownership of each collection.** Two classes mutating the same list is where the bugs start.

## Common Mistakes

- Putting every method on `Library` and leaving `Book` and `Member` as bare data holders.
- Printing inside model methods, so they can't be reused or tested.
- Forgetting `self.` and quietly creating a local variable instead of updating the object.
- Letting two classes mutate the same list, so neither one can be trusted.
- Storing a member's borrowed books as a copy rather than a reference, so returns never register.
