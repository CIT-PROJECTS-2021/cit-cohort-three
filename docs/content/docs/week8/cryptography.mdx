Cryptography protects information by transforming it into a form that is hard
to read without a key.

<Callout type="info">
You don’t need to invent cryptography — use trusted libraries and standards.
</Callout>

## Key Terms
- **Plaintext**: readable message.
- **Ciphertext**: encrypted message.
- **Encryption**: converting plaintext to ciphertext.
- **Decryption**: converting ciphertext back to plaintext.

## Types of Cryptography
### Symmetric
Same key used for encryption and decryption.

Examples: AES, DES, Blowfish.

**Use cases**
- Encrypting files on disk
- Securing data between trusted systems

### Asymmetric
Different keys for encryption (public) and decryption (private).

Examples: RSA, Diffie‑Hellman, ECC.

**Use cases**
- Secure key exchange
- Digital signatures

<Steps>
<Step title="Encrypt">
Use a key to turn plaintext into ciphertext.
</Step>
<Step title="Transmit">
Send the ciphertext over an untrusted channel.
</Step>
<Step title="Decrypt">
Use the correct key to recover the original message.
</Step>
</Steps>


## Hashing is not encryption

Everything above is **reversible** — that's the point of a key. Hashing is the
opposite: a one-way digest you can compare but never undo.

```python
import hashlib

print(hashlib.sha256(b"hello").hexdigest())
# 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
```

| | Encryption | Hashing |
| :- | :- | :- |
| Reversible | yes, with the key | no |
| Needs a key | yes | no |
| Output size | grows with input | fixed |
| Use for | messages you must read later | passwords, integrity, IDs |

Password storage, file checksums, and content IDs all belong to hashing — they
have their own page: [Hash Functions](/docs/week8/hash-functions).

## Symmetric Encryption Example (Fernet)
Fernet provides authenticated symmetric encryption.

```python
from cryptography.fernet import Fernet

key = Fernet.generate_key()
f = Fernet(key)

token = f.encrypt(b"secret message")
print(token)

print(f.decrypt(token))
```

**Expected output (example)**
```
b'gAAAAABl...'
b'secret message'
```

## Asymmetric Encryption Example (RSA)
Asymmetric encryption uses a public key to encrypt and a private key to decrypt.

```python
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives import hashes

private_key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
public_key = private_key.public_key()

message = b"hello rsa"
ciphertext = public_key.encrypt(
    message,
    padding.OAEP(
        mgf=padding.MGF1(algorithm=hashes.SHA256()),
        algorithm=hashes.SHA256(),
        label=None,
    ),
)

plaintext = private_key.decrypt(
    ciphertext,
    padding.OAEP(
        mgf=padding.MGF1(algorithm=hashes.SHA256()),
        algorithm=hashes.SHA256(),
        label=None,
    ),
)

print(plaintext)
```

**Expected output**
```
b'hello rsa'
```

## Digital Signature Example
Digital signatures prove that a message was created by the holder of a private key.

```python
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives import hashes

private_key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
public_key = private_key.public_key()

message = b"verify me"

signature = private_key.sign(
    message,
    padding.PSS(
        mgf=padding.MGF1(hashes.SHA256()),
        salt_length=padding.PSS.MAX_LENGTH,
    ),
    hashes.SHA256(),
)

try:
    public_key.verify(
        signature,
        message,
        padding.PSS(
            mgf=padding.MGF1(hashes.SHA256()),
            salt_length=padding.PSS.MAX_LENGTH,
        ),
        hashes.SHA256(),
    )
    print("Signature valid")
except Exception:
    print("Signature invalid")
```

**Expected output**
```
Signature valid
```

## Don't roll your own

<Callout type="warn">
Every example on this page uses the `cryptography` library rather than
hand-written maths. That's deliberate. Cryptographic code fails silently — it
produces plausible-looking output while being trivially breakable — so the
implementation details matter more than almost anywhere else in programming.

Write the [Caesar cipher](/docs/week8/caesar-cipher) to understand substitution.
Use a reviewed library for anything real.
</Callout>

## Rules

1. **Encryption is reversible with the key; hashing is not reversible at all.** Pick by whether you need the original back.
2. **Symmetric encryption uses one shared key; asymmetric uses a public key to encrypt and a private key to decrypt.**
3. **The algorithm is public; only the key is secret.** A scheme that depends on its method staying hidden is not secure.
4. **Never write your own cryptographic primitives.** Use `cryptography` or `hashlib`.
5. **Never commit keys to version control.** Use environment variables or a `.env` file that is git-ignored.
6. **Generate keys with a cryptographic random source** — `secrets` or `os.urandom()`, never `random`.
7. **A Fernet token decrypts only with the exact key that produced it.** Lose the key and the data is gone.
8. **Encrypt passwords never; hash them always.** See [Hash Functions](/docs/week8/hash-functions).

2. Explain in one sentence each: plaintext, ciphertext, key, digest.
3. You're storing user passwords. Encryption or hashing — and why?
4. You're sending a message that the recipient must read. Encryption or hashing?
5. Sign a message, change one character of it, then verify. What happens?

## Common Mistakes

- Storing plaintext passwords, or encrypting them instead of hashing them.
- Using MD5 or SHA-1 for anything security-sensitive.
- Writing your own encryption instead of using a reviewed library.
- Committing keys to Git. Keys belong in environment variables.
