These are the notes for a twelve-week Python course. They're written to be read
in order, but they're also built so you can drop into any topic and find your way
out again.

Two minutes reading this page will save you time later.

## How a topic page is laid out

Every topic page follows the same order, so you always know where to look:

1. **The idea**, in a paragraph or two
2. **Examples** you can copy and run, with their output shown
3. **Common mistakes** — the errors people actually hit
4. **Practice** — questions to try before moving on
5. **Keep going** — links to the next page and related topics

If you're revising rather than learning, skip to Common Mistakes. It's the
densest part of every page.

## Getting around

<Steps>
<Step title="Search">
Press **⌘K** (Mac) or **Ctrl+K** (Windows/Linux) anywhere and type. This is the
fastest way to reach a specific topic and you should use it constantly.
</Step>
<Step title="Sidebar">
The full course, in order. Weeks collapse and expand.
</Step>
<Step title="Previous / Next">
At the bottom of every page. Following these takes you through the entire course
in the intended order without touching the sidebar.
</Step>
<Step title="Cross-links">
Terms link to the page that explains them. If something mid-page assumes
knowledge you don't have, the link is right there — follow it, then come back.
</Step>
</Steps>

## How to actually learn this

<Callout type="tip" title="The one habit that matters">
Type every example. Don't copy and paste. Typing it forces you to read every
character, and the errors you make while typing teach you more than the working
code does.
</Callout>

- **Break the examples on purpose.** Change a value, remove a line, misspell a
  name. Read the error. Errors are the fastest feedback you'll get.
- **Do the practice questions before reading on.** They're short and they're the
  difference between recognising something and being able to write it.
- **Struggle for fifteen minutes before looking anything up.** Then look it up.
- **Keep a scratch file.** One `scratch.py` you overwrite constantly beats
  carefully organised examples you never run.

## If you get stuck

- **Read the error message.** The last line names the problem; the lines above
  say where. See [Exceptions](/docs/week3/exceptions).
- **Print things.** Put `print()` on either side of the line you suspect.
- **Check the Common Mistakes section** on the page you're reading. Your bug is
  probably there.
- **Search these notes** with ⌘K before searching the web.
- **Ask.** Bring the code, the full error, and what you expected to happen.
