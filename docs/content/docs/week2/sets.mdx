Sets are unordered collections of unique, immutable items. The set itself is
mutable, so you can add or remove elements.

<Callout type="info">
Use sets for fast membership checks and removing duplicates.
</Callout>

## Creating Sets
```python
numbers = {1, 2, 3}
mixed = {1.0, "Hello", (1, 2, 3)}

from_list = set([1, 2, 2, 3])  # {1, 2, 3}
```

An empty set must be created with `set()`:
```python
empty = set()
```

**Uniqueness demo**
```python
nums = {1, 2, 2, 3}
print(nums)  # {1, 2, 3}
```

## Adding and Removing
```python
s = {1, 3}
s.add(2)
s.update([2, 4, 5])

s.remove(4)   # raises KeyError if missing
s.discard(10) # no error if missing
```

## Set Operations
```python
a = {1, 2, 3, 4}
b = {3, 4, 5, 6}

print(a | b)  # union
print(a & b)  # intersection
print(a - b)  # difference
print(a ^ b)  # symmetric difference
```

## Membership and Iteration
```python
print(2 in a)  # True

for item in a:
    print(item)
```

## Frozenset
```python
f = frozenset([1, 2, 3])
# f.add(4)  # AttributeError
```


## Rules

1. **Elements are unique.** Adding a duplicate does nothing and raises no error.
2. **Elements must be hashable.** Adding a list or dict raises `TypeError`; tuples are fine.
3. **Sets are unordered.** There is no indexing — `s[0]` raises `TypeError` — and no reliable iteration order.
4. **The set itself is mutable; `frozenset` is not.**
5. **An empty set is `set()`.** `{}` creates an empty dictionary.
6. **`remove()` raises `KeyError` when the item is absent; `discard()` does not.**
7. **Set operators need sets on both sides.** `{1,2} | [3]` raises `TypeError`; the method forms (`.union()`, `.intersection()`) accept any iterable.
8. **Membership testing is O(1)**, regardless of size.

## Common Mistakes
- Expecting sets to preserve order.
- Adding unhashable types like lists to a set.
- Using `remove` without checking membership.
