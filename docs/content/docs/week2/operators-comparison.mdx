Comparison operators compare values and return `True` or `False`.

<Callout type="tip">
For checking if a value is inside a range, chain comparisons:
`0 <= x <= 10`.
</Callout>

## Operators
| Operator | Meaning | Example |
| --- | --- | --- |
| `==` | equal to | `5 == 3` |
| `!=` | not equal to | `5 != 3` |
| `>` | greater than | `5 > 3` |
| `<` | less than | `5 < 3` |
| `>=` | greater than or equal | `5 >= 3` |
| `<=` | less than or equal | `5 <= 3` |

## Example
```python
x = 10
y = 12

print(x > y)   # False
print(x < y)   # True
print(x == y)  # False
print(x != y)  # True
print(x >= y)  # False
print(x <= y)  # True
```

## Comparing Different Types

Numeric types compare across the board, so `5 == 5.0` is `True`.

Strings compare lexicographically — dictionary order, by Unicode code point:

```python
print("apple" < "banana")   # True
print("Apple" < "apple")    # True  — uppercase sorts first
```

Tuples compare element by element, left to right, stopping at the first
difference:

```python
print((1, 2, 3) > (1, 2))   # True  — longer, and equal so far
print((1, 2, 3) > (1, 5))   # False — 2 < 5 decides it
```

## Use Cases

- Range checks: `0 <= score <= 100`
- Sorting and ordering data

## Rules

1. **All six return `True` or `False`** and nothing else.
2. **`==` compares values; `is` compares identity.** They are not interchangeable.
3. **Comparisons can be chained.** `1 < x < 10` is valid and means `1 < x and x < 10`.
4. **Ordering comparisons need compatible types.** `"3" > 1` raises `TypeError`; only `==` and `!=` work across unrelated types.
5. **Strings compare by Unicode code point, left to right.** `"Z" < "a"` is `True`, so case matters when sorting.
6. **Never test floats with `==`.** Compare with a tolerance: `abs(a - b) < 1e-9`.

## Common Mistakes
- Comparing strings without considering case sensitivity.
- Confusing `==` with `is` for identity.
- Assuming different types always compare as false.
- Forgetting string comparison is case-sensitive — `"A" < "a"` is `True`.
