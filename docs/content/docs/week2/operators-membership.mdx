Membership operators test whether a value is in a sequence or collection.

<Callout type="tip">
For dictionaries, membership checks the **keys**, not the values.
</Callout>

## Operators
| Operator | Meaning | Example |
| --- | --- | --- |
| `in` | value is present | `"a" in "cat"` |
| `not in` | value is absent | `4 not in [1, 2, 3]` |

## Example
```python
text = "Hello world"
data = {1: "a", 2: "b"}

print("H" in text)        # True
print("hello" in text)    # False (case-sensitive)
print(1 in data)          # True (checks keys)
print("a" in data)        # False
```

## Note
For dictionaries, `in` checks keys, not values.


## Rules

1. **`in` works on any container or iterable** — string, list, tuple, set, dict, range. On a non-container it raises `TypeError`.
2. **On a dictionary, `in` tests keys, not values.** Use `value in d.values()` for values.
3. **On a string, `in` tests substrings**, so `"ell" in "hello"` is `True`.
4. **`in` is O(1) on sets and dicts, O(n) on lists and tuples.** For repeated lookups over large data, use a [set](/docs/week2/sets).
5. **`not in` is a single operator**, and is preferred over `not (x in y)`.
6. **`in` always returns a boolean.**

## Common Mistakes
- Checking dictionary values with `in` instead of keys.
- Forgetting that membership checks are case‑sensitive.
- Using `in` on the wrong type.
