## How to approach them

<Callout type="tip">
Struggle for fifteen minutes before looking anything up. That fifteen minutes is
where the learning happens. Reaching for the answer early feels productive and
teaches you very little.
</Callout>

1. **Read the whole brief first.** Then write down what it's actually asking for.
2. **Get the smallest version working.** One account, one file, one endpoint.
   Then extend it.
3. **Run it constantly.** Don't write fifty lines and hope.
4. **When it breaks, read the error.** The last line names the problem; the lines
   above say where. See [Exceptions](/docs/week6/exceptions).
5. **Then compare** with the solution or a classmate's approach. Different is
   often fine, so ask why theirs is different rather than assuming yours is wrong.
